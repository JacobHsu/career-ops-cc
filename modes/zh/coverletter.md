# 模式：104 推薦信（自我介紹信）

用於產生可直接複製貼上至 104 應徵頁面「自我介紹」欄位的繁體中文信件。

**這個模式是檔案驅動的。** 不接受對話中貼 JD 文字或只給「公司+職稱」。所有資料必須事先放在對應路徑，模式只負責讀檔產出信件。

**不要替使用者送出。只產生可複製的文字，由使用者確認後自行貼入。**

## 唯一輸入

使用者必須提供 104 職缺 URL 或 jobNo：

```
/career-ops coverletter https://www.104.com.tw/job/8xxxxx
/career-ops coverletter 8xxxxx
```

從 URL 末段或直接的 jobNo 取得 `{job_id}`。

## Step 0 — 前置條件檢查（嚴格 + 顯式 checklist）

執行任何讀檔或產出之前，**先把檢查結果列給使用者看**，格式如下：

```
== 推薦信前置檢查（jobNo: {job_id}）==

必要檔案：
  [{✅|❌}] cv.zh.md
  [{✅|❌}] jds/{job_id}.md
  [{✅|❌}] config/profile.yml
  [{✅|❌}] modes/_profile.md

選用檔案（影響品質）：
  [{✅|—}] examples/coverletter/past-letters.md
  [{✅|—}] reports/{對應該公司的評估報告}
  [{✅|—}] article-digest.md
```

**所有「必要檔案」皆為 ✅ 時**，才繼續產出。對話接續：
> 前置檢查通過，開始讀取資料並產出推薦信...

**只要有任何必要檔案為 ❌**：立刻停止，**不要產信、不要讀其他檔案**。針對缺檔給出修補指令：

- `cv.zh.md` ❌ → 「請先建立 `cv.zh.md`（繁中履歷）」
- `jds/{job_id}.md` ❌ → 「請先執行 `npm run fetch104 -- https://www.104.com.tw/job/{job_id}`」
- `config/profile.yml` ❌ 或 `modes/_profile.md` ❌ → 「請先完成 onboarding（執行 `/career-ops` 沒有特定模式即可進入引導）」

任何一項缺檔，**不接受對話中貼上替代資料**。模式專心做一件事：把檔案資料寫成信。

## 資料來源

| 路徑 | 必要性 | 用途 |
|------|--------|------|
| `cv.zh.md` | 必讀 | 繁中 CV，所有經歷與數字的唯一來源 |
| `jds/{job_id}.md` | 必讀 | fetch-jd 抓取的完整 JD 結構 |
| `config/profile.yml` | 必讀 | 個人定位、薪資、narrative |
| `modes/_profile.md` | 必讀 | 使用者個人化設定 |
| `examples/coverletter/past-letters.md` | 若存在則讀 | 過去寫過的推薦信彙整，作為文風延續參考 |
| `reports/{num}-*.md` | 若存在則讀 | 該公司的評估報告，補充 fit 分析 |
| `article-digest.md` | 若存在則讀 | 補充 proof points |

**規則**：所有經歷、數字、技術只能來自 `cv.zh.md`，不可憑空填入。

### 過去推薦信參考（examples/coverletter/past-letters.md）

每次產出新信前：

1. 讀取 `examples/coverletter/past-letters.md`（若存在）
2. 作為**文風延續**參考——使用者過去滿意的句法、開頭、收尾節奏
3. **不複製內容**——只學語感

如果檔案不存在，跳過此步驟，僅靠 `cv.zh.md` 與 JD 產出。

**注意**：`output/coverletters/` 是輸出資料夾，**只放新產出，不作參考來源**。

## 流程

1. **Step 0**：前置條件檢查（嚴格，缺檔即停止）
2. 讀 `jds/{job_id}.md` → 擷取公司名、職稱、主要職責、必要技能、加分條件
3. 讀 `cv.zh.md` + `config/profile.yml` + `modes/_profile.md`
4. 讀 `examples/coverletter/past-letters.md`（若存在）
5. 讀 `reports/{num}-*.md`（若該公司有評估報告）
6. 依下方結構產出信件
7. 寫入 `output/coverletters/{job_id}-{YYYY-MM-DD}.md`
8. 在對話中顯示信件 + 來源摘要 + 需確認處

## 信件結構

四段，總長 250–350 字，繁體中文：

**第一段（定位，2–3 句）**
- 說明自己是誰、幾年資歷、核心專長
- 點出與這個職缺最直接相關的一個身份

**第二段（匹配，3–4 句）— CAR 框架**
- C（情境）：在 {公司/專案} 期間，面對 {具體挑戰}
- A（行動）：採用 {技術/方法}，負責 {具體工作}
- R（成果）：最終 {可驗證的結果}
- 來源只能是 cv.zh.md，不可編造

**第三段（動機，2–3 句）**
- 說明為什麼對這家公司或這個職位有興趣
- 必須呼應 JD 原文詞彙（產品、技術方向、業務特性）

**第四段（收尾，1–2 句）**
- 期待有機會進一步說明
- 不要用「感謝您百忙中撥冗閱讀」這類空泛套語

## 語氣守則

- 直接、專業，不誇大
- 技術詞彙保留英文（React、CI/CD、LLM 等）
- 不用「熱愛學習」「積極主動」「抗壓性高」「自我驅動」「團隊合作佳」
- 不用第一人稱「我」開頭每一句
- 避免翻譯腔
- 具體數字優先（「3 人團隊」比「小團隊」有力）

### JD 用詞鏡像（三個層級）

**鼓勵借用 JD 用詞——這證明你讀過 JD**。但「怎麼用」決定是加分還是扣分。三層級：

#### Level 1 ❌ 整句抄錄（禁用）

```
「對於貴公司『以資訊技術支援生物科技、協助農業管理』的方向感到認同」
```

特徵：加「」+ 完整 JD 句 + 官腔動詞（「感到認同」「深感興趣」）
HR 反應：「你只是把我們網站的話貼回來」

#### Level 2 ✅ 關鍵詞融入（推薦）

```
過去做過 GIS 與即時資料系統，希望能延伸到動植物與農業管理場景
```

特徵：借 JD 的關鍵詞（「動植物管理」）但融入自己的句子；不加引號；後面立刻接自己的經驗
HR 反應：「他知道我們做動植物管理」

#### Level 3 ✅✅ 顯式回應（最高）

```
看到貴公司把資訊技術導入農業這個結合很少見，過去我在公部門 LBS 專案處理過類似的領域應用
```

特徵：用自己的話復述 JD 核心 + 立刻連到自己的經驗
HR 反應：「他真的讀過 JD 並能對應到自己的經驗」

### AI 寫作味偵測（禁止模式）

以下是 Level 1 的延伸——ChatGPT 寫求職信的指紋，**全部禁用**：

**禁用句型：**
- 「對於貴公司 XX 的方向感到認同」← 中式官腔代表
- 「對於 XX 深感興趣」「對貴公司 XX 有高度興趣」
- 「貴公司在 XX 領域享有盛名」「貴公司在業界佔有領導地位」
- 「期望能有所貢獻」「希望能與貴公司共同成長」
- 「致力於」「秉持」「擁抱」這類自傳體大詞

**禁用結構：**
- **直接用「」引號抄 JD 整句**（短關鍵詞如「翻轉課堂」「資料科學」可加引號，整句不可）
- 整段都是書面語、沒有任何口語節奏
- 動機段沒有具體 動作 / 經驗 / 產品 連結，全部抽象表態

**判準：「讀者覺得你在 copy-paste，還是覺得你在回應？」**

| | 抄錄（Level 1）| 鏡像（Level 2/3）|
|---|---|---|
| 加引號? | 通常加 | 不加（或只短關鍵詞加）|
| 完整句 | 是 | 改寫 |
| 動詞 | 「致力於」「秉持」官腔 | 「做過」「希望延伸」口語 |
| 後面接什麼 | 通常接抽象表態 | 立刻接自己的具體經驗 |

## 輸出格式

寫入 `output/coverletters/{job_id}-{YYYY-MM-DD}.md`，並在對話中顯示同樣內容：

```
## {Company} {Role} — 推薦信

{信件正文，直接可複製}

---
字數：{N} 字
來源：cv.zh.md + jds/{job_id}.md（+ past-letters + report {num}，視實際讀到的列出）
需確認：{如有空白或不確定處，列於此}
```

## 注意事項

- 所有經歷、數字、技術只能來自 `cv.zh.md`，不可憑空填入
- JD 資訊不足時不要自己補，標 `{請補充：XXX}`
- 使用者對輸出不滿意時，詢問哪個段落需要調整，不要整封重寫
- 寫入 `output/coverletters/` 後，使用者若滿意可手動把正文貼到 `examples/coverletter/past-letters.md`，下次會學
