# 模式：reviewletter（推薦信專業審稿）

扮演**台灣資深 HR / 招募主管**角色，審核 `/career-ops coverletter` 產出的推薦信，給出量表評分與具體修改建議。

**只審稿、不改稿。** 修改決策由使用者執行。

## 唯一輸入

使用者必須提供 jobNo：

```
/career-ops reviewletter 8xxxxx
```

從 `output/coverletters/{jobNo}-*.md` 找**檔名日期最新的**那篇。若同日多篇，取字典序最後一個。

## Step 0 — 前置條件檢查（嚴格 + 顯式 checklist）

執行任何讀檔或審稿之前，先列出 checklist：

```
== 審稿前置檢查（jobNo: {job_id}）==

必要檔案：
  [{✅|❌}] output/coverletters/{job_id}-*.md（最新一篇）
  [{✅|❌}] jds/{job_id}.md
  [{✅|❌}] cv.zh.md

選用檔案（影響審稿嚴謹度）：
  [{✅|—}] examples/coverletter/past-letters.md
  [{✅|—}] reports/{對應該公司的評估報告}
```

**任何必要檔案 ❌ → 立即停止**並給修補指令：

- `output/coverletters/{job_id}-*.md` ❌ → 「請先執行 `/career-ops coverletter {job_id}` 產出推薦信」
- `jds/{job_id}.md` ❌ → 「請先執行 `npm run fetch104 -- https://www.104.com.tw/job/{job_id}`」
- `cv.zh.md` ❌ → 「請先建立 `cv.zh.md`（繁中履歷）」

**全部 ✅ → 對話接續**：
> 前置檢查通過，開始審稿...

## 資料來源

| 路徑 | 必要性 | 用途 |
|------|--------|------|
| `output/coverletters/{job_id}-*.md` | 必讀 | 待審的推薦信 |
| `jds/{job_id}.md` | 必讀 | 比對職缺需求與信件匹配度 |
| `cv.zh.md` | 必讀 | 驗證真實性（信件每個事實必須在 CV 找得到）|
| `examples/coverletter/past-letters.md` | 若存在則讀 | 文風基準線（過去成功信的句法） |
| `reports/{num}-*.md` | 若存在則讀 | 該公司 fit 分析，輔助判斷信件是否強化 fit |

## 審稿框架（六項評分）

每項 1–5 分，附理由 + 具體修改建議。

### 1. 真實性（True-to-CV）

- 信件中每個經歷、公司、技術、數字必須在 `cv.zh.md` 找得到對應
- 標出無對應的句子，列為「⚠️ 待驗證」或「❌ 編造」
- **此項 < 3 分時，整體不通過，必須先修真實性**

### 2. 套話偵測（Cliché Detection）

#### 2A. 禁用詞清單

掃描禁用詞，命中即扣分：

```
熱愛學習、積極主動、抗壓性高、自我驅動、團隊合作佳
貴公司在業界享有盛名、貴公司深感興趣
感謝您百忙中撥冗閱讀、敬請惠予機會
期望能有所貢獻、希望能與貴公司共同成長
致力於、秉持、擁抱（自傳體大詞）
```

每命中一個 -1 分。

#### 2B. AI 寫作味偵測（ChatGPT 指紋）

**JD 用詞分三層判定**（鏡像 JD 是加分，整句抄錄才扣分）：

| Level | 範例 | 評分影響 |
|-------|------|---------|
| Level 1 整句抄錄 + 引號 | 「對於貴公司『XXX』的方向感到認同」 | **扣 2 分**，上限 3/5 |
| Level 2 關鍵詞融入 | 「過去做過 GIS，希望延伸到動植物管理場景」 | **不扣分**（鼓勵）|
| Level 3 顯式回應 + 經驗 | 「看到 XX 這個結合很少見，過去做過類似的 YY」 | **加分** |

**Level 1 的具體偵測訊號：**

- 加「」引號 + 整句 JD 原文（短關鍵詞加引號 OK）
- 官腔句型：「對於 XX 感到認同」「對 XX 深感興趣」「貴公司在 XX 領域享有盛名」
- 自傳體大詞：「致力於」「秉持」「擁抱」
- 整段書面語、沒有口語節奏、後面接抽象表態

**判定標準：**
- 整句抄 JD（加引號 + 完整句）≥ 1 處 → 套話偵測上限 3/5
- 命中官腔句型 ≥ 2 個 → 套話偵測上限 3/5
- 修改建議必須給「Level 2 或 Level 3」的 after 版本，不能只刪不補

### 3. CAR 框架完整度（第二段）

第二段必須有：
- **C**（情境）：當時面對的具體挑戰？
- **A**（行動）：採用的技術或方法？
- **R**（成果）：可驗證的結果？

三項齊備 = 5 分，缺一 -1。

### 4. JD 匹配度（Job Fit）

對照 `jds/{job_id}.md`：
- 信件有沒有針對該職缺的「主要職責」回應？
- 「必要技能」有沒有從 cv.zh.md 帶出對應經歷？
- 「公司特色 / 產品方向」有沒有在第三段呼應？

5 分 = 三項都到位；3 分 = 通用版可套用到別家；1 分 = 偏題。

### 5. 結構與字數

- 4 段（定位 / 匹配 / 動機 / 收尾）齊備？
- 字數 250–350？
- 段落長度均衡（不要某段 5 行、某段 1 行）？

### 6. 語氣與可讀性

- 不誇大、不過度謙卑
- 技術詞彙保留英文
- 不每句都「我」開頭
- 沒翻譯腔
- 讀完一遍能記住一個亮點？

**對應職缺**：{Company} {Role}

   - 原文：「{引用句子}」
   - 建議：「{改寫後句子}」
   - 理由：{為什麼要改}

（同上格式）

#### 🟢 微調（可保留）
（同上格式）

{2–3 句總評，模擬真實 HR 拿到這封信的第一印象}

- [ ] 修改 X 點嚴重問題後可投遞
- [ ] 建議直接重寫第 N 段

## 注意事項

- **嚴格依 cv.zh.md 判斷真實性**，CV 沒寫的就視為編造，不能因為「合理推測」放行
- **不直接改信**，只給 before / after 建議，由使用者決定
- 修改建議的 after 句必須**也是真實可查**（來自 cv.zh.md），不要為了好聽自己編
- 若信件完全沒問題，誠實寫「通過，可直接投遞」，不要硬找問題湊
- HR 角色定位：嚴格但建設性，不羞辱，不打官腔
